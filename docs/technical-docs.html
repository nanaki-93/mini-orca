Mini-Orca Technical Guide

A local-first Go coding assistant with a 5-hub Terminal UI and a loopback HTTP daemon. It finds verified & AI issues, generates architecture docs, suggests features, and runs native ADK workflows with explicit human review, Apply and recovery.

3 Binaries · 25 Packages · 5 TUI Hubs · 63 API Routes
01 · FIND ISSUES

Static Rules + Scoped AI Analysis

Combines deterministic Go AST security rules (go-rules-v1) and sandboxed go vet / go test scans with resumable per-file AI analysis across Bugs, Performance, and Security. Verified tool findings and AI suggestions are never mixed.

02 · SYNTHESIZE DOCS

C4 / Arc42 / ADR Engineering Handbook

Builds a structured specification (.mini-orca/project-docs.json) from the AST index and architecture analysis: system purpose, C4 components, dependencies, runtime scenarios, ADRs with tradeoffs, operational runbooks, and domain glossary.

03 · SUGGEST FEATURES

Goal-Aligned Feature Discovery

Generates up to 5 new feature ideas per run (.mini-orca/changes/features.json) grounded in your saved project goals, AGENTS.md guidelines, and indexed files, with automatic duplicate suppression.

04 · GUARDED CHANGES & AGENTS

Native ADK Workflows with Apply & Undo

Prepares changes across 1–8 captured Go/Markdown files per task, with separate generation, test generation, verification, specialist review and human-input outcomes. Reviewed missions coordinate bounded children in isolated worktrees. Diff Apply, integration and Undo remain explicit host-owned actions.

Three Core Safety Guarantees

1. Read-Only Navigation

Opening a project, browsing files, switching TUI views, or previewing a run never calls an LLM, never executes project code, and never writes source files.

2. Explicit Consent & Trust

Remote/CLI model calls require per-request confirm_remote_provider. Running go test or Git checkout/merge requires separate per-revision execution-trust.

3. Guarded Apply & Undo

Every edit must pass checks, receive human diff Review (reviewed_hash), and verify file SHA-256 hashes before Apply or Undo.

Guarded ADK Change Workflow (internal/app/agentruntime/change_graph.go)

The native graph records create, generate_tests, verify, review and human_review separately. Specialist review uses a parallel join; repairs use a bounded opt-in loop. The four review groups below summarize this flow rather than prescribe a fixed stage count.

ADK imports stay in internal/app/agentruntime; private durable sessions, budgets and evidence belong to internal/app/agentstate. The host retains consent and mutation authority. See the capability matrix, configuration and migration, and worker and inspector guide. Fake-provider conformance does not establish live model quality or cloud IAM behavior.

Unified Project Analysis Engine (analysis_run*.go, analysis_queue*.go)

Preflights the repository (queue_id + preview_id), then runs 4 per-file stages in bounded windows (default 100 files, 15m budget, 2 attempts/stage).

STAGE A · semantic
Semantic Review

Owner: semantic_review.go (file-analysis-v16). Uses bug scope. Classifies risks into bugs, performance, or security with 2–6 word titles.

STAGE B · performance
Performance Review

Owner: performance_review.go (performance-file-v7). Uses analyze scope. Returns line-bounded bottlenecks; enclosing symbol is resolved from the AST index.

STAGE C · security_rules
Deterministic AST Rules

Owner: security_rules_scan.go (go-rules-v1). Zero LLM calls. Detects go.tls.insecure-skip-verify (CWE-295) & go.shell.dynamic-command (CWE-78).

STAGE D · security_ai
Advisory Security AI

Owner: security_review.go (security-file-v4). Requires explicit security_review: true. Redacts source-line token sequences from stored/returned prose.
